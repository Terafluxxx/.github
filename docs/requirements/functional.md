# Функциональные требования

## FR-01. Регистрация и авторизация

Система должна позволять пользователю:

- зарегистрироваться;
- войти в систему;
- выйти из системы;
- получить информацию о текущем профиле.

Для авторизации используется JWT.

## FR-02. Работа с организациями

Система должна:

- хранить пользователей и бизнес-данные в рамках организации;
- связывать товары, поставщиков и закупки с организацией;
- запрещать пользователю доступ к данным другой организации.

## FR-03. Управление товарами

Система должна позволять:

- создавать товар;
- просматривать список товаров;
- просматривать карточку товара;
- редактировать товар;
- удалять товар;
- искать товары;
- фильтровать и сортировать список.

## FR-04. Учёт складских остатков

Система должна:

- хранить текущий остаток товара;
- отображать остатки;
- позволять обновлять остаток;
- проверять корректность количества.

## FR-05. Учёт продаж

Система должна:

- хранить продажи товаров;
- добавлять данные о продажах;
- получать продажи за выбранный период;
- рассчитывать количество продаж за период.

Для MVP основной расчётный период — последние 30 дней.

## FR-06. Работа с поставщиками

Система должна:

- хранить поставщиков;
- связывать поставщиков с товарами;
- хранить цену товара у поставщика;
- хранить срок поставки;
- хранить минимальную партию;
- отображать доступных поставщиков товара.

Выбор поставщика в MVP выполняется пользователем.

## FR-07. Импорт CSV

Система должна поддерживать импорт CSV для:

- товаров;
- остатков;
- продаж;
- поставщиков.

После импорта система должна отображать:

- количество добавленных записей;
- количество обновлённых записей;
- количество ошибок.

## FR-08. Анализ продаж и остатков

Система должна автоматически рассчитывать:

- средние продажи в день;
- количество дней запаса;
- точку заказа;
- целевой запас;
- рекомендуемое количество закупки.

## FR-09. Определение состояния товара

Система должна присваивать товару одно из состояний:

- `CRITICAL`;
- `NEED_PURCHASE`;
- `NORMAL`;
- `NO_SALES`.

## FR-10. Формирование рекомендаций

Система должна формировать список товаров, которым требуется закупка, и рассчитывать:

- рекомендуемое количество;
- ориентировочную стоимость;
- причину формирования рекомендации.

## FR-11. Dashboard

Система должна отображать:

- общее количество товаров;
- количество критических товаров;
- количество товаров к закупке;
- количество потенциальных дефицитов;
- рекомендуемый бюджет;
- список критических товаров и рекомендаций.

## FR-12. Создание закупки

Система должна позволять пользователю:

- создать закупку на основании рекомендации;
- выбрать поставщика;
- добавить позиции закупки;
- рассчитать итоговую стоимость;
- просматривать созданные закупки;
- изменять статус закупки.

Поддерживаемые статусы:

- `DRAFT`;
- `CREATED`;
- `ORDERED`;
- `RECEIVED`;
- `CANCELLED`.

## FR-13. Объяснение рекомендаций

Для каждой рекомендации система должна показывать пользователю объяснение, на основе каких показателей она сформирована: текущий остаток, средние продажи, срок поставки и рекомендуемое количество.

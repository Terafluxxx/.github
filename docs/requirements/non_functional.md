# Нефункциональные требования

Численные значения ниже являются целевыми метриками MVP и должны подтверждаться тестированием.

## 1. Производительность

### NFR-PERF-01
Не менее 95% обычных REST-запросов должны обрабатываться сервером не более чем за **2 секунды** при штатной нагрузке.

### NFR-PERF-02
Dashboard должен формироваться и загружаться не более чем за **3 секунды** при объёме до **10 000 товаров**.

### NFR-PERF-03
Импорт CSV-файла объёмом до **10 000 строк** должен завершаться не более чем за **30 секунд**.

### NFR-PERF-04
Формирование рекомендаций для **10 000 товаров** должно выполняться не более чем за **30 секунд**.

## 2. Доступность

### NFR-AVL-01
Целевая доступность системы — не менее **99% в месяц**, без учёта планового технического обслуживания.

### NFR-AVL-02
Перезапуск приложения не должен приводить к потере ранее сохранённых данных.

### NFR-AVL-03
Данные PostgreSQL должны храниться в постоянном Docker Volume.

## 3. Безопасность

### NFR-SEC-01
Пароли пользователей должны храниться только в виде BCrypt-хэшей.

### NFR-SEC-02
Все защищённые API должны требовать успешной аутентификации.

### NFR-SEC-03
Для авторизации используется JWT.

### NFR-SEC-04
Пользователь организации A не должен иметь доступ к товарам, продажам, остаткам, поставщикам и закупкам организации B.

### NFR-SEC-05
Все входные данные должны проходить серверную валидацию.

### NFR-SEC-06
В production взаимодействие пользователя с системой должно выполняться по HTTPS.

## 4. Масштабируемость

### NFR-SCL-01
Backend не должен хранить пользовательское состояние в памяти между запросами, чтобы допускать запуск нескольких экземпляров приложения.

### NFR-SCL-02
Архитектура должна позволять горизонтально масштабировать Backend без изменения бизнес-логики.

### NFR-SCL-03
Архитектура должна позволять в дальнейшем подключать внешние источники данных, например 1С, МойСклад и маркетплейсы.

## 5. Удобство использования

### NFR-USA-01
Основные разделы приложения должны быть доступны из единого навигационного меню.

### NFR-USA-02
Основной сценарий от загрузки данных до создания закупки должен выполняться внутри одной системы без необходимости внешних расчётов.

### NFR-USA-03
После импорта CSV пользователь должен видеть количество добавленных, обновлённых и ошибочных записей.

### NFR-USA-04
Каждая рекомендация должна содержать понятное текстовое объяснение причины её формирования.

### NFR-USA-05
Пользовательские сообщения об ошибках не должны содержать stack trace и внутренние технические детали Backend.
